# AUDIT_REPORT.md — AI Exporter v0.9.5 → v1.0

Audit performed on the repository as found, before any modification.
Date: 2026-11-14. Audit was carried out by reading the source, then by running the
project's own harnesses (`npm run check`, `npm test`, `npm run artifacts`) and by
probing the real renderers in headless Chrome (`tools/probe.js`).

Machine: Windows, Node v24.19.0, Chrome (packaged Chromium), Python 3.14 with
`pypdf` and `pymupdf`.

## 1. Existing architecture

```
Chat page (chatgpt.com / claude.ai / gemini / deepseek)
      │  content/content.js        site adapters, DOM → blocks
      ▼
utils/parser.js                   KaTeX/MathML, tables, lists, code → typed blocks
      │  background/service_worker.js  message router + schema gate
      ▼
export/export.html + export.js    workspace UI: format cards, preview, progress,
      │                           cancel, downloads, success/error modals
      ▼
utils/exporter.js                 normalised document model + renderers
      │                           HTML/print (MathML), TXT, Markdown, JSON, PNG canvas
      ├─ utils/docx.js            OOXML package + OMML equations (hand-written ZIP)
      ├─ utils/mcq.js             question/option folding
      └─ utils/document-theme.js  palettes
```

Execution flow for an export: `export.js` → `exporter.build(chat, format, options)`
→ `normalizeChat()` → format renderer → `Blob` → `chrome.downloads` (completion
confirmed by the download event, not by the click).

PDF is not generated by a library: the workspace renders the standalone document
into a same-origin iframe and calls `contentWindow.print()`. Everything the print
dialog sees is the exact document the HTML format produces.

Verification assets that already existed and were used as the audit's ground truth:

| Tool | Purpose |
| --- | --- |

| `tools/run-tests.js` + `cdp.js` | 92 browser checks against the real modules |
| `tools/generate-artifacts.js` | builds all seven formats and validates the bytes |
| `tools/probe.js` | evaluates expressions against the real exporter in Chrome |

## 2. Existing functionality (found working, preserved)

* Seven formats: PDF (print), DOCX, HTML, Markdown, TXT, JSON, PNG.
* A normalised document model with validation (`normalizeChat`, `validateChat`).
* A hand-written TeX → MathML compiler (fractions, indexed roots, scripts,
  `\sum`/`\int`, matrices, cases, aligned, `\boxed`, `\pmod`, fonts, Greek,
  comments, multi-line formulas, escaped commands).
* A TeX → OMML writer producing real `m:f`, `m:rad`, `m:sSup`, `m:sSub`,
  `m:nary`, `m:m`, `m:limLow`, `m:eqArr` — i.e. editable Word equations.
* A readable plain-text maths fallback used by TXT and the PNG canvas.
* Cooperative cancellation (`cancelRequested`, `ExportCancelled`), a four-stage
  progress card, `modal-cancel`, download-completion confirmation, error modal,
  retry, object-URL release.
* Standalone HTML with a CSP, escaped page content and repeated table headers.
* DOCX: 11 package entries, well-formed XML, numbering for nine list levels,
  repeating table header rows, embedded media, CSS-free syntax colouring.
* PNG: DPI written into a real `pHYs` chunk, scale reduced automatically when a
  poster would exceed the canvas limit, and the reduction reported as a warning.

## 4. Confirmed bugs

Severity: **High** = silent content loss or wrong mathematics; **Medium** =
visibly wrong output in one format; **Low** = cosmetic/edge.

### BUG-1 (High) — a price beside a formula was parsed as mathematics
Input `It costs $5 for $x^2$ units.` produced maths `5for`, swallowed the `$5`,
and left `x$` as text. Reproduced in HTML/PDF, TXT/PNG and Markdown.
Root cause: the single-dollar branch of the inline pattern

```js
/\$[^$\n]+?\$(?![0-9])/
```

accepted a closing `$` that followed a space, so `$5 for $` matched first. The
`(?![0-9])` guard only protected `$5 and $10`.
Files: `utils/exporter.js` (`plainInline`, `formatInline`, `markdownInline`).

### BUG-2 (High) — Word used its own inline pattern with the same defect
`utils/docx.js` carried `\$[^$\n]+\$`, so the same sentence reached Word as
maths `5 for`, with the real `x^2` demoted to prose and ` units and \` typeset
as an equation. Verified by extracting `<w:t>` runs from `word/document.xml`:
`["…it costs ", " units and $10 for the rest."]` with `x^2` outside mathematics.
Root cause: two hand-rolled delimiter scanners instead of one shared token.
Files: `utils/docx.js` (`inline`).

### BUG-3 (Medium) — escaped dollar printed its backslash
`Price \$5 and \$10` rendered as `\$5` in HTML/PDF/TXT; after the naive fix the
pair `\$5 … \$10` still paired into an equation, because the escape was only
handled after the maths scan.
Files: `utils/exporter.js`.

### BUG-4 (Low) — empty formula raised a maths-error badge
`$$ $$` compiles to no nodes, which the error path reported as a rendering
failure (`[data-tex-error]`), adding a warning badge and "could not be
rendered" status text for nothing.
Files: `utils/exporter.js` (`formatInline`).

### BUG-5 (Medium) — Word integrals were not n-ary objects
`\int_0^1 x^2 dx` reached Word as `∫` with `m:sSubSup`; only `\sum` (which
carries `\limits`) became `m:nary`. A bare glyph does not stretch to its
integrand and shows limits as ordinary scripts.
Files: `utils/docx.js` (`bigOperator`, `naryXml`).

## 5. Potential risks examined and judged not to be bugs

| Risk | Finding |
| --- | --- |
| Very long PNG | `pngFor` reduces raster scale and errors honestly if even 0.35× will not fit; it never crops. |
| Object URLs | image preview and download URLs are revoked on re-render and on replace. |
| Duplicate exports | `busy` guard on every entry point. |
| Raw stack traces | only `error.message` reaches the modal; details stay in the console. |
| HTML injection | page text is escaped, the document ships without scripts and with a CSP. |
| Unmatched `$` | left as literal text on purpose (it is prose, not mathematics). |
| Print dialog | cannot report "saved"; the UI says "Print dialog open" and never claims a file exists. |

## 6. Files requiring modification

* `utils/exporter.js` — inline maths token, escaped dollars, empty formulas.
* `utils/docx.js` — shared inline token, escaped dollars, n-ary integrals.
* `selftest.js` — four regression checks.
* `tools/artifact-page.js`, `tools/generate-artifacts.js` — regression fixture and
  two artifact-level assertions.

## 7. Recommended (and executed) implementation order

1. One shared inline-maths token, consumed by every renderer (HTML/print, TXT,
   Markdown, Word) — removes the class of defect rather than one instance.
2. Escaped delimiters parked on a sentinel before scanning.
3. Empty formulas dropped.
4. Word n-ary detection widened to integrals.
5. Regression checks at unit level (`selftest.js`) and at byte level
   (`generate-artifacts.js`), then regenerate every artifact and inspect it.

## 8. Remediation audit addendum (post-review pass)

The v1.0 review of `37da75f` / `ce9e560` raised five defects and four code-quality
findings. Re-auditing the committed implementation confirmed all of them:

| Confirmed defect | Severity | Evidence |
| --- | --- | --- |
| PNG had no multi-page fallback | High | `pngFor()` had a single canvas and a scale ladder ending in refusal |
| Equation fitting could clip at the 0.72 floor | Medium | `fitDisplayMath()` shrank only; no wrapping path existed |
| Incomplete thread extraction was silent | High | `collectThread()` returned entries with no completeness signal |
| DOCX had no page numbers, header/footer or sections | Medium | one bare `w:sectPr`; no header/footer parts in the package |
| BUG-2 had artifact-level coverage only | Low | no selftest assertion read `document.xml` for it |

Code-quality findings confirmed as described in the review: the list-depth clamp
existed in three modules, the scroll walk in two loops, one `\u00b7` escape was
inconsistent with its file, and `fitDisplayMath()` reached into the preview DOM
from the workspace controller. All are addressed; see
`POST_IMPLEMENTATION_REVIEW.md`.

No new defect was found in the areas the review did not touch (parser, MCQ
folding, document model validation, download confirmation, security posture).
