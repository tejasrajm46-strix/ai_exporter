# AI Exporter Agent Instructions

## Mission

Build a production-ready Chrome Manifest V3 extension that lets a user export
their current AI chat locally. Supported sites are ChatGPT, Claude, Gemini, and
DeepSeek. The extension must not send chat content to a server.

## Non-negotiable constraints

- Do not add Notion integration, a backend, telemetry, or remote data uploads.
- Never include remotely hosted executable code, scripts, or stylesheets.
  Manifest V3 extension code and any third-party libraries must be packaged
  locally with the extension.
- Read a page's conversation only after an explicit user action. Do not scrape
  unrelated pages or persist conversation content.
- Keep permissions and host matches limited to the functionality and supported
  sites. Explain any proposed permission expansion before making it.
- Do not claim a format or fidelity option works until it has an end-to-end
  implementation and a verification check.
- The exported document is always the **full transcript**. Never make content
  selection implicit: a turn may only be left out because the user unticked it
  in the export view's message panel.
- Preserve accessible labels, keyboard operation, visible focus, and readable
  error/empty states in the popup and injected controls.

## Project structure

- `manifest.json`: MV3 permissions, supported site matches, popup, service
  worker registration, and the packaged `icons/` set.
- `background/service_worker.js`: context-menu setup and validated download
  requests from extension pages.
- `content/content.js` and `content/content.css`: page-side message handling and
  optional custom-selection controls.
- `popup/popup.html`, `popup/popup.js`, and `popup/popup.css`: compact extension
  UI, preferences, status, and user-triggered actions.
- `utils/parser.js`: site-aware DOM extraction into a shared message schema.
- `utils/exporter.js`: local conversion of parsed messages into export data.
- `export/export.js`: the preview tab - message picker, theme/zoom/toggles,
  downloads, print-to-PDF.
- `tools/make-logo.py`: the single source of the brand mark. It emits the SVG
  and the PNGs from one geometry spec so they cannot drift; run it with
  `python tools/make-logo.py` (or `--concepts <dir>` for alternatives).
- `assets/`: README artwork and samples (`hero.png`, `logo*.svg`,
  `logo-512.png`, `document-preview.jpg`, `sample-export.pdf`).
- `icons/`: `icon16/32/48/128.png`, generated by the same script.
- `selftest.html`: fixture-driven checks against the parser and the export
  engine. Open it over the dev server; it needs no extension host.

Keep content-script code isolated from popup code. Load `utils/parser.js` before
`content/content.js` in the manifest. Do not use remote modules or assume the
popup can import arbitrary web dependencies.

## Shared conversation schema

Use a documented, stable shape for each extracted message. At minimum include:

```js
{
  id: "stable-per-page-message-id",
  role: "user | assistant | system | unknown",
  text: "plain text content",
  blocks: [ /* structured content, see below */ ],
  codeBlocks: [{ language: "javascript | unknown", code: "..." }],
  formulas: [{ tex: "...", display: false }],
  timestamp: "ISO-8601 string or null"
}
```

`blocks` is what exporters render from, so no format has to re-parse site HTML:

```js
{ type: "heading", level, text }        { type: "paragraph", text }
{ type: "list", ordered, items }        { type: "quote", text }
{ type: "code", language, code }        { type: "table", head, rows }
{ type: "image", src, alt }             { type: "formula", tex }
{ type: "divider" }                     { type: "subheading", text, number }
```

There is no `html` field on purpose: the parser keeps structure, and exporters
re-escape text, so page-provided markup is never injected into an export.
Inline text carries lightweight markers - `**bold**`, `*italic*`, `` `code` ``,
`$tex$` - which exporters convert back to their own markup.

The parser must tolerate site DOM changes: use small, site-specific selector
adapters, verify candidate containers, deduplicate results, and fail with an
empty result rather than exporting page chrome. Do not use brittle positional
selectors as the only detection method. Keep extracted text and code faithful to
the page. Do not execute page-provided HTML or scripts in an export document.

## Architecture rules that keep this small

- One export surface: the export view (`export/`). The popup, the in-page
  selection bar and the context menu only build a chat payload and ask the
  service worker to open that view, so no export logic runs in a context that
  can be closed mid-flight.
- The popup never parses and never builds a file. The content script never
  downloads. The service worker never touches file data - it validates the
  payload, stashes it in `chrome.storage.session`, and opens the view.
- The export view reads the payload once and removes it, so conversation text is
  never left in storage. Its per-message ticks live in page memory only.
- One content model: `sectionsFor(chat)` turns messages into turns, and both the
  printed document and the PNG poster render from it. There is no second
  "clean"/outline mode to keep in sync - content is the full transcript.
- Print quality comes from `@page` margins plus zeroed sheet padding in
  `@media print`, so every page gets margins; the on-screen sheet is only
  dressing for the preview.
- The printable light theme has exactly one surface per block: code sits on
  `--code-bg` and nothing inside it re-paints a background. `.code pre code`
  resets `padding/background/color/border` so a nested `<pre>` can never inherit
  the inline-code chip background, and `::selection` uses the pale
  `--accent-soft` tint so dragging a selection over a panel stays light. Keep
  both rules when editing `DOCUMENT_CSS`.

## Interaction requirements

- Popup actions: Custom Export, quick export formats PDF, Markdown, Text, DOCX,
  Image, and JSON; settings for timestamps, code highlighting, and dark PDF.
- Show the detected conversation/message count when available. If detection
  fails, say: "Could not detect chat on this page. Please refresh and try
  again." Keep the message actionable and do not silently export an empty file.
- Custom selection mode adds a labeled checkbox to each recognized message and
  a bottom action bar only while at least one message is selected. Include a
  way to cancel/exit selection mode.
- The export view always starts with every message ticked, offers quick
  selectors (Everything / Answers / Prompts / None), shows the selected count,
  and disables saving when nothing is ticked instead of writing an empty file.
- Tell the user to untick "Headers and footers" in the print dialog. Chrome
  stamps its own date/title/URL strip into the page margins, and no CSS can
  remove it. The guidance lives in the status text and the Save-as-PDF `title`.
- Show progress or completion feedback for exports, and useful errors when a
  site is unsupported, a conversation is empty, or a download fails.
- Settings are preferences only and belong in `chrome.storage.local`; do not
  store chat transcripts there.

## Verification checklist

- `manifest.json` parses as JSON and Chrome accepts the extension via
  `chrome://extensions` > Developer mode > Load unpacked.
- Every path in `icons` and `action.default_icon` exists on disk.
- Popup and service worker have no console errors on a supported site and an
  unsupported site.
- Each supported site's parser returns messages in visible conversation order
  with the correct roles and without navigation/sidebar text.
- Selection exports exactly the checked messages and can be exited cleanly.
- Every enabled format opens correctly and downloads with the expected name;
  no empty or truncated export is reported as successful.
- Settings persist across popup reopen and do not persist conversation data.
- Long conversations do not freeze the page or popup; errors do not expose
  conversation contents.

## Current status

Version 0.2.0 is a working extension: parsing, selection mode, all six formats,
the export view and the brand are implemented, and `selftest.html` passes 55/55.

The document is the full transcript on every export surface: a cover page, then
one continuous flow of turns with role chips, rendered from `sectionsFor`. The
printed layout relies on `@page { margin: 15mm 14mm }` with the on-screen sheet
chrome stripped in `@media print`, so a turn that spills onto the next page
still gets a top margin. The light theme keeps code and output panels light
(`--code-bg: #f8fafc`); only `[data-theme="dark"]` keeps dark panels
(`--code-bg: #0d0208`). The running "AI Exporter" header is gone from the
document, and there are no static page numbers: pagination falls where the
content lands, so a printed number would be a guess.

The export view adds a message panel: every turn starts ticked, quick selectors
set the set in one click, and the selection filters the preview, the print job
and every download. It also reports an estimated page count and disables the
save buttons when nothing is ticked.

The brand is generated, not hand-drawn: `tools/make-logo.py` is pure standard
library (no Pillow, no cairosvg) and writes SVG and PNG from the same geometry,
so `assets/logo.svg` and `icons/icon128.png` cannot drift apart. A change to the
mark means re-running that script, not editing the PNGs.

**Verified against a live ChatGPT conversation** (the fixture in `selftest.html`
is copied from it). Facts worth not re-learning:

- A turn is `<section data-testid="conversation-turn-N">`; the role attribute
  (`data-message-author-role`) is on a descendant, and the stable id is the inner
  `data-message-id` - prefer it over the positional `data-testid`.
- Assistant body is `div.<hashed>_content.markdown.prose`; user body is a
  `.whitespace-pre-wrap` div inside a div with the role attribute.
- A code block is a `<pre>` that contains a CodeMirror viewer whose own
  `<pre class="cm-content"><code>` holds the code, so read
  `pre.querySelector("code")` and never walk into a `<pre>` twice.
- The language label is a short `<div>` **inside** the `<pre>`, before the code.
  Class-based detection finds nothing on current ChatGPT.
- Tables are wrapped in `div.TyagGW_tableContainer`; headings, `hr`, `ul/ol`,
  `blockquote`, inline `code` and `strong` all appear inside the markdown body.
- `fetch()` from a chat page to `127.0.0.1` is blocked by the site CSP, so the
  real parser cannot be injected live; copy markup into the fixture instead.
- Chrome's print pipeline stamps its own header/footer strip in the page
  margins; the user has to untick "Headers and footers".

Also verified in this repo: roles, ordering, ids, inline and display math,
markup escaping, and the export engine (Markdown, TXT, JSON, DOC, the print
document in both themes, that the light theme keeps code on paper, the nested
`<pre>` reset, the selection tint, the print rules, highlighting on/off, summary
and next-steps cards, filename slugging, PNG rendering).

Verified by hand: extension loads unpacked, popup detection and error states,
selection mode, the export view against a stubbed hand-off (picker counts,
quick selectors, empty selection disabling the save buttons, page estimate), the
print dialog on a supported page, and every generated icon/SVG.

One judgement call, flagged rather than assumed: the "dark box in the text box"
report was read as "the printable light theme must have no dark surface", and
fixed with the `.code pre code` reset plus the `::selection` tint. If the report
actually meant the inline-code chip should stay dark on purpose, revert that
pair and say so here.

Not yet verified against a live page: the Claude, Gemini and DeepSeek adapters
(they were updated from a maintained multi-site exporter's documented DOM and
from the naming change from `.font-claude-message` to `.font-claude-response`).
Test each one before claiming support.

Not done on purpose (see README "Deliberate limits"): vendored KaTeX/Prism,
in-document page numbers, a table of contents, an outline/clean content mode,
and image embedding for the PNG poster.

Before claiming a change works, run `selftest.html` and, for anything that reads
a live page, repeat the manual checklist on the real site. Browser cache can
serve a stale `selftest.html`; load it with a `?v=<timestamp>` suffix.
